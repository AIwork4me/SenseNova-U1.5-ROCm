# Finding: root cause of the t2i silent corruption on torch ≥ 2.9 stacks — patch 0002's MATH pre-scaling double-applies (2026-09-01)

**Verdict: the torch 2.12.0+rocm7.14.0 (and nightly 2.15) wheels are exonerated. The corruption is a numerical bug in our own `patches/0002-sdpa-rocm-math-backend-compat.patch`, gated to ROCm torch ≥ 2.9. No upstream report is warranted.** Fixing only the scale semantics on the 2.12 stack restores bit-class-correct generation (verified quantitatively and visually).

## Mechanism

`_sdpa_attn_func` (modeling_qwen3.py, patch 0002) restricts the SDPA dispatcher to MATH on ROCm torch ≥ 2.9 and, instead of passing `scale`, pre-multiplies `q` by `softmax_scale` and calls `scaled_dot_product_attention(..., scale=None)`. The assumption — that MATH would then not rescale — is false: **`scale=None` means "apply the default 1/√E"** on every stack tested (verified independently on torch 2.8.0+rocm6.3 and 2.12.0+rocm7.14.0: `MATH scale=None` matches an explicit fp32 manual attention at 1/√E to rel 1.7e-3, while the pre-scale pattern deviates from the intended scaling by rel 0.738 identically on both stacks). Effective scale becomes `softmax_scale × 1/√128 = 1/128` instead of `1/√128` — every generation-mode attention logit is **under-scaled by √128 ≈ 11.3×**, collapsing softmax to near-uniform mixing. The version gate (`_torch_ver >= (2, 9)`) is why torch 2.8 computes correctly (stock path passes `scale` directly) while the official 2.12 wheel and the upstream nightly both corrupt. Only `forward_gen` routes through this function — hence the path-specificity (VQA/understanding use transformers' own SDPA path with explicit `scale`).

## Evidence chain (all artifacts under outputs/debug-2.12-corruption/, gitignored; harness scripts alongside)

1. **Deterministic, harness-faithful reproduction**: with forward hooks on the real pipeline (same loader/args/seed 2026/1664×2496/50 steps), the 2.12 stack reproduced the archived corrupt PNG byte-identically (sha256 `190104b8…`), proving the hooks do not perturb numerics and the corruption is deterministic. The 2.8 stack under the identical harness produced a good natural image (hcorr 0.973 / block64-corr 0.711).
2. **Stage table** (100 predict calls, per-field sha/rel-diff vs the 2.8 run): initial noise `z_in` BITSAME at step 0; `embeds` 1.4e-4 (benign prefix bf16 noise); language-tower output already 0.118 at step 0; `fm_out` 0.72 — divergence enters inside the tower and the ConvDecoder merely amplifies it.
3. **Layer table**: prefix-mode (understanding) attention outputs differ by ~1e-6 (benign); **generation-mode layer-0 attention output std jumps 4.42 → 29.7** — the injection point is gen-mode attention.
4. **attn0 internals** (captured on both stacks for step-0 call 0): `indexes` (t/h/w positions) BITSAME; all six RoPE cos/sin tables rel = 0.0 (bit-identical — RoPE fully exonerated); q/k/v entering `_flash_or_sdpa` rel ≈ 5e-4; its output rel = 4.76. The divergence is entirely inside `_sdpa_attn_func`, with identical kwargs (`softmax_scale=0.08839`, `causal=False`) on both stacks.
5. **Standalone probe** (`sdpa_probe.py`, no model): F.sdpa MATH `scale=None` applies the default on both stacks; the patch's pre-scale pattern is wrong on both stacks by the same rel 0.738 — the bug is stack-independent, engagement is version-gated.
6. **ConvDecoder exonerated by same-input replay**: feeding the identical captured `fm_in` (1,4096,78,52) through `fm_modules['fm_head']` on both stacks gives rel 6.3e-4, each stack bit-deterministic across repeat calls.
7. **Decisive fix experiment**: monkey-patching only `_sdpa_attn_func` on the 2.12 stack (keep BSHD↔BHSD transposes + GQA repeat + MATH-only ctx; pass `scale=softmax_scale` explicitly instead of pre-scaling) regenerates the same prompt/seed to a statistically-good image — hcorr 0.974 / block64 0.711 / mean 68.4 / std 71.5 vs the 2.8 reference's 0.973 / 0.711 / 68.3 / 72.1 — **and an independent vision-model check reads it as a coherent ink-wash "八仙" movie poster with no grid artifacts**. One numerical change, corruption eliminated.

This also retroactively explains every prior observation: the nightly (2.15) corruption family (same version gate), "MATH-only bit-identical to stock" on nightly (both paths run the same pre-scale code), the Aug-23 `t2i-torch212-fixed.png` being corrupt (ran on a ≥ 2.9 stack with patches applied), and why the #194447/#194498 family op probes (which test F.sdpa directly with explicit `scale`) all passed while the model still corrupted.

## A false positive worth recording

The first "corrected" attempt replaced `_sdpa_attn_func` without the BSHD↔BHSD transposes, feeding flash-layout tensors straight into F.sdpa (attention computed over heads-as-tokens). It changed the output statistics (hcorr 0.939) but the image was still a finer woven texture — **caught only by the mandatory vision check**, and a warning that hcorr alone cannot classify fine-grid corruption (block64-corr ≈ 0.001 is itself an anomaly: natural images sit around 0.6–0.9). Quantitative signatures must be paired with semantic verification before declaring victory.

## Recommended fix (ready to apply on approval)

Amend patch 0002's `_needs_fix` branch: keep `sdpa_kernel([SDPBackend.MATH])`, drop the `q_bhsd * _scale` pre-scale, and pass `scale=softmax_scale` directly to `scaled_dot_product_attention` (the `TypeError` fallback for pre-scale-kwarg torch versions can pre-scale only when it will also pass `scale=1.0`, or fall back to the manual path). Validated end-to-end by experiment 7 above on the official 2.12 wheel stack. Until the patch lands, the repo guidance stands (gen-validated torch 2.8 stack for generation); after it lands, `STACK=714` generation should be re-validated with the byte-level A/B protocol from docs/results/validation/ before switching the default.
